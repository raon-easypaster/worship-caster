# 자동 업데이트 서명 열쇠 (만든 사람만 봅니다)

예배송출의 [지금 업데이트]는 **목사님 컴퓨터에 있는 비밀 열쇠로 서명한 배포만** 설치합니다.
깃허브 계정을 누가 빼앗아 가짜 파일을 올려도, 서명이 맞지 않으면 교회 컴퓨터들은 설치하지 않습니다.

- **비밀 열쇠**: `~/.worshipcaster-signing/update-signing-key.pem`
  - 목사님 맥에만 있습니다. 저장소(깃허브)에는 절대 넣지 않습니다.
- **공개 열쇠**: `lib/updater.js` 의 `UPDATE_PUBLIC_KEYS`
  - 앱 안에 들어가 서명을 확인하는 데 씁니다. 남이 보아도 괜찮습니다.

## 1. 열쇠 만들기 (처음 한 번만, 이미 만들어 두었습니다)

```bash
node tools/signing-key.js new
```

- 비밀 열쇠를 만들고, 앱에 넣을 공개 열쇠를 보여 줍니다.
- 열쇠가 이미 있으면 덮어쓰지 않고 멈춥니다.
- 2026-11-19에 만들어 공개 열쇠를 `lib/updater.js`에 넣어 두었습니다.

## 2. 보관하기 (꼭 해 주세요)

비밀 열쇠 파일은 아주 작은 글자 파일 하나입니다. **한 벌 더** 안전한 곳에 두세요.

1. 파인더에서 ⌘+Shift+G → `~/.worshipcaster-signing` 입력 → 이동
2. `update-signing-key.pem` 파일을 다음 중 한두 곳에 복사합니다.
   - 서랍에 두는 USB 메모리
   - 비밀번호 관리 앱(1Password, 애플 '암호' 앱의 메모 등)에 내용을 붙여 넣기
3. 이런 곳에는 두지 마세요.
   - 깃허브
   - 카카오톡·메일·공유 드라이브처럼 남이 볼 수 있는 곳

새 맥으로 옮기면 같은 자리(`~/.worshipcaster-signing/update-signing-key.pem`)에 다시 넣어 두면 됩니다.

맞는 열쇠인지 확인:

```bash
node tools/signing-key.js check
```

## 3. 배포할 때

`bash build-dist.sh` 가 저절로 서명합니다.

- 맨 먼저 열쇠가 앱의 공개 열쇠와 짝인지 확인합니다. 열쇠가 없거나 짝이 아니면 배포 파일을 만들지 않습니다.
- 다 만들면 `dist/SHA256SUMS.txt.sig` 가 생깁니다.
- **깃허브 배포에 다음 파일을 꼭 함께 올리세요.**
  - `WorshipCaster-update.wcu`
  - `SHA256SUMS.txt`
  - `SHA256SUMS.txt.sig`
- `.sig` 가 빠지면 앱은 자동 설치를 하지 않습니다. 대신 [받는 곳 열기]로 안내합니다.

## 4. 열쇠를 잃었을 때

- 그 뒤로 만드는 배포는 이미 나눠 준 앱들이 **자동 설치하지 않습니다.**
  - 서명이 맞지 않으므로 [받는 곳 열기]로만 안내합니다.
- 그래서 **다음 한 번은 교회들이 손으로 새 앱을 받아 바꿔 넣어야** 합니다.
- 자료(예배 순서·찬양·설정)는 그대로 남습니다.

다시 시작하는 방법:

1. `node tools/signing-key.js new` 로 새 열쇠를 만듭니다.
2. 나온 공개 열쇠로 `lib/updater.js` 의 `UPDATE_PUBLIC_KEYS` 를 바꿉니다.
3. 새 버전을 배포하고, 교회들에 "이번 한 번만 손으로 바꿔 넣어 주세요"라고 알립니다.
4. 그다음 버전부터는 다시 자동 설치가 됩니다.

## 5. 열쇠가 새어 나간 것 같을 때

남이 가짜 업데이트에 서명할 수 있게 됩니다. 4번처럼 새 열쇠로 바꾸고, 손으로 바꿔 넣는 버전을 배포하세요.

(열쇠를 잃지 않았다면 미리 바꿀 수도 있습니다.

1. 새 공개 열쇠를 `UPDATE_PUBLIC_KEYS` 에 **더한** 버전을 옛 열쇠로 서명해 먼저 배포합니다.
2. 그다음 버전부터 새 열쇠로 서명합니다.

이렇게 하면 손으로 바꿔 넣는 일이 없습니다.)
